Antes que nada: ¿qué es una consulta SQL?

Si nunca escribiste una, empezá por acá. Una consulta es una frase que le pide algo a la base de datos, siempre con esta forma:

SELECT columnas — qué quiero ver FROM tabla — de dónde lo saco WHERE condición — qué filas quiero (opcional) GROUP BY columna — cómo agrupar (opcional) ORDER BY columna; — cómo ordenar (opcional)

Siempre en este orden — pero solo usás las líneas que necesitás. Por ejemplo, esta consulta válida solo usa dos:

SELECT * FROM envios;

Se lee: "traeme todas las columnas (*) de la tabla envios".

Conceptos de esta herramienta

Un repaso corto de las ideas que estás viendo en acción en las otras dos pestañas.

PK

Llave primaria

El identificador único de cada fila de una tabla — como tu número de DPI. Nunca se repite y nunca está vacía. En el diagrama ER la vas a ver marcada en rojo.

FK

Llave foránea

El número de la llave primaria de OTRA tabla, guardado como referencia. Así una tabla "apunta" a una fila específica de otra tabla, sin repetir sus datos. Marcada en verde en el diagrama.

1 → N

Relación uno a muchos

La forma más común de relación: una fila de una tabla (por ejemplo, un agente) puede estar conectada con muchas filas de otra (sus envíos). La flecha dorada del diagrama muestra hacia dónde apunta esa relación.

ER

Diagrama ER

Un mapa visual de las tablas y cómo se conectan entre sí. Cada caja es una tabla; cada línea es una relación entre una llave primaria y una llave foránea. Este diagrama se dibuja solo, leyendo la base de datos real.

JOIN

JOIN

La instrucción SQL que reconecta tablas separadas para responder una pregunta. INNER JOIN solo trae filas que tienen pareja en ambas tablas; LEFT JOIN también trae las que no la tienen.

¿Por qué?

¿Por qué separar en tablas?

Para no repetir el mismo dato una y otra vez. Si guardás el nombre y la sede de un agente en una sola fila de "agentes", cada envío solo necesita guardar su id_agente — no todos esos datos otra vez.

Orden típico para construir una relación

El patrón que vas a repetir cada vez que conectes dos tablas nuevas.

  1. Creá la tabla "padre" — la que va a ser referenciada (por ejemplo, departamentos), con su llave primaria.
  2. Creá la tabla "hija" — la que va a tener la referencia (por ejemplo, empleados), incluyendo una columna que sea llave foránea.
  3. Conectalas con REFERENCES — al definir la columna, o después con ALTER TABLE ... ADD COLUMN ... REFERENCES.
  4. Consultalas juntas con JOIN — para responder preguntas que necesitan datos de ambas tablas a la vez.
